# Revisions

The design's revisions, newest first. A revision changes what the API is or does: a field, a
default, a rule, a mapping, a platform decision or a cloud limit. Changes to wording and layout are
not revisions. A change to the design adds its line to the open revision, or opens the next one once
the last is agreed.

| Fixed cloud blocks replaced<br>Changed             | Settings of one implementation move from the fixed cloud blocks into an open list of provider configurations, one kind per implementation, so a new cloud or an on-premises implementation never changes the core kinds (principles 2, 3 and 8). |
| Classes for defaults and constraints<br>Added      | Classes hold a deployment's defaults (`template`) and the values a user cannot change (`enforced`) (principle 5).                                                                                                                                |
| Defaults moved from infralib<br>Changed            | A deployment's defaults move from values passed through infralib into classes (principle 5).                                                                                                                                                     |
| Unsupported features refused<br>Changed            | An object that requests a portable feature its class does not support is refused instead of ignored (principle 1).                                                                                                                               |
| Entries checked by their implementation<br>Changed | Provider configuration entries are checked by their implementation (principle 10).                                                                                                                                                               |
| CI checks against published schemas<br>Added       | CI checks provider configuration entries against every implementation's published schema (principle 10).                                                                                                                                         |
| Field groups limited to units<br>Changed           | Field groups exist only as units or subsystems (principle 13).                                                                                                                                                                                   |
| Tags on every created resource<br>Added            | Every resource the platform creates carries workspace and Zone tags, on every service.                                                                                                                                                           |
| Implementation status moved<br>Changed             | Values of one implementation move from `status.<cloud>` to `status.provider`, in the shape its provider configuration kind's status defines; on RDS, `status` becomes `state` (principle 4).                                                     |
