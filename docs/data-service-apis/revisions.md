# Revisions

The design's revisions, newest first. A revision changes what the API is or does: a field, a
default, a rule, a mapping, a platform decision or a cloud limit. Changes to wording and layout are
not revisions. A change to the design adds its line to the open revision, or opens the next one once
the last is agreed.

#### 3 in progress

Shared engine settings come in layers: an object and its class each reference a list of parameter
objects, so a team puts settings all its services share beneath one service's own tuning.

| Change                                                     | Details                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Shared settings in layers<br>Changed, Common               | `parametersRef` becomes `parametersRefs`, a list of at most eight, on PostgreSQL, MariaDB, Valkey, Kafka and RabbitMQ objects and their classes. Settings merge key by key, a later value winning: the class's list in order, then the object's, then the object's own `parameters`. Each parameters object is referenced once in a list and names no other.                                                                                                                                             |
| Class record kept on the object<br>Changed, Common         | The class values an object received at creation or at its last sync, the class's `enforced`, `parametersRefs` and provider configuration, are kept in the annotation `<group>/class-record`, which only the platform writes and which a restore brings back; it replaces `status.classSync`. Admission compares every change with the recorded `enforced`, so a locked field is refused at any time, not only at creation and sync. An object without a record keeps its resources and waits for a sync. |
| Standalone objects<br>Added, Common                        | An object without a class, where the deployment has no default class, is standalone: its own provider configuration entry chooses the implementation and sets every required setting, the implementation's defaults fill the rest, and it has no template, enforced values or class record.                                                                                                                                                                                                              |
| Class added once to a standalone object<br>Changed, Common | `className` may be added once to a standalone object, if the class runs on the object's implementation; adding it applies nothing until the first sync. It is still never changed or removed.                                                                                                                                                                                                                                                                                                            |
| In-cluster implementations<br>Added, Common                | A deployment may install an implementation that runs in its Kubernetes cluster beside its cloud's; a class chooses between them, and a standalone object with entries for both is refused.                                                                                                                                                                                                                                                                                                               |
| CloudNativePG<br>Added, PostgreSQL                         | `PostgreSQLCluster` runs on CloudNativePG through `PostgreSQLCNPGConfig` (`cpu`, `memory`, `storageClass`, `fromBackup`, `id`), with backups through the Barman Cloud plugin to the deployment's object store; the mapping, composed resources and limits are on the Cloud Mapping tab.                                                                                                                                                                                                                  |

#### 2 2026-11-23

Settings of one implementation move out of fixed cloud blocks into classes and provider
configurations, so a deployment sets its own defaults and limits, and a new cloud or an on-premises
implementation is added without changing the core kinds.

| Change                                                                | Details                                                                                                                                                                                                                                                                                                         |
| --------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Fixed cloud blocks replaced<br>Changed, Common                        | Settings of one implementation move from the fixed cloud blocks into an open list of provider configurations, one kind per implementation, so a new cloud or an on-premises implementation never changes the core kinds (principles 2, 3 and 8).                                                                |
| Classes for defaults and constraints<br>Added, Common                 | Classes hold a deployment's defaults (`template`) and the values a user cannot change (`enforced`) (principle 5).                                                                                                                                                                                               |
| Defaults moved from infralib<br>Changed, Common                       | A deployment's defaults move from values passed through infralib into classes (principle 5).                                                                                                                                                                                                                    |
| Unsupported features refused<br>Changed, Common                       | An object that requests a portable feature its implementation does not support is refused instead of ignored (principle 1).                                                                                                                                                                                     |
| Entries checked by their implementation<br>Changed, Common            | Provider configuration entries are checked by their implementation (principle 10).                                                                                                                                                                                                                              |
| CI checks against published schemas<br>Added, Common                  | CI checks provider configuration entries against every implementation's published schema (principle 10).                                                                                                                                                                                                        |
| Field groups limited to units<br>Changed, Common                      | Field groups exist only as units or subsystems (principle 13).                                                                                                                                                                                                                                                  |
| Tags on every created resource<br>Added, Common                       | Every resource the platform creates carries workspace and Zone tags, on every service.                                                                                                                                                                                                                          |
| Implementation status moved<br>Changed, Common                        | Values of one implementation move from `status.<cloud>` to `status.provider`, in the shape its provider configuration kind's status defines; on RDS, `status` becomes `state` (principle 4).                                                                                                                    |
| Applied entries and value sources<br>Added, Common                    | `status.providerConfig`, the entries applied and ignored, and `status.effective`, each value's source (principle 4).                                                                                                                                                                                            |
| Version conversion for kept names<br>Added, Common                    | A kind that keeps its name from today's API serves `v1alpha1` and `v1alpha2` through one stored version and a conversion webhook, so today's manifests still apply; a field only one version has is kept in an annotation, so a write through either version loses no field.                                    |
| Today's behaviour until the parent moves<br>Added, Common             | An object of a kind that keeps its name keeps today's parent, Secret and defaults while its parent reference names today's kind in `kind`; the team removes `kind` once the parent has moved. `KafkaUser` and `RabbitMQBroker` keep writing today's Secret beside the design's until the migration period ends. |
| Ownership of an observed resource<br>Added, Common                    | An observed object takes ownership of its resource when the user removes `observe`, once, and sets the common fields in the same edit, if the resource's Zone tag names the object's Zone; a field left unset keeps the resource's value (principle 9).                                                         |
| Nothing created inside an untagged observed resource<br>Added, Common | No user, database or other kind inside it is created on an observed resource without a Zone tag; the kind reports the refusal in a condition (principle 9).                                                                                                                                                     |
| Contents never deleted with their parent<br>Added, Common             | An object that holds others, such as a cluster with databases or a bucket with objects, is deleted only once the user has emptied it; a Crossplane `Usage` of the parent blocks its deletion until the kinds inside are gone (principle 14).                                                                    |
| Workload identity first<br>Added, Common                              | An application logs in with its workload identity where the implementation supports it, and static credentials are the fallback (principle 15).                                                                                                                                                                 |
| Lower values ignored, not refused<br>Changed, Common                  | A disk size, Valkey version or topic partition count below the real one is accepted and ignored, with a condition, instead of refused, so an increase the cloud rejects can be corrected.                                                                                                                       |
| RDS-managed admin password kept<br>Changed, Common                    | On RDS the admin password stays managed by RDS, as today, and the admin Secret is read from it, so taking ownership of today's instance changes no password.                                                                                                                                                    |
| Entries matched without their version<br>Added, Common                | The entry that applies is found by its group and kind, whatever its version, and converted to the version the class uses; an object holds one entry per group and kind.                                                                                                                                         |
| Class changes applied on request<br>Added, Common                     | An object keeps its class and the class's values from creation, with `className` written then; a new value of the annotation `<group>/class-sync` applies the class's current values once, and `ClassSynced: False` shows a class changed since. `enforced` is checked at creation and at a sync only.          |
| Foreground deletion everywhere<br>Changed, Common                     | Every kind is deleted in the foreground, so an object stays in deletion while the cloud refuses to delete one of its resources; today only the PostgreSQL and MariaDB kinds are.                                                                                                                                |
| Secret taken over at migration<br>Added, Common                       | An object that takes ownership of a resource today's API created takes over the same-named Secret today's object owns, so a migration needs no `secretName`.                                                                                                                                                    |
| Missing required settings refused<br>Added, Common                    | An object for which neither its provider configuration entry nor its class sets a setting its implementation cannot run without, such as a machine size, is refused when applied.                                                                                                                               |
| Observing refused until the allowlist<br>Changed, Common              | The platform refuses `observe: true` until a Zone's Argo CD project allows only the platform's and Kubernetes' own groups, which the tag check depends on (principle 9).                                                                                                                                        |
| Rule for new portable features<br>Added, Common                       | A need becomes a portable feature once two or more implementations support it, in a revision of the design (principle 1).                                                                                                                                                                                       |
| Cluster kind renamed<br>Changed, PostgreSQL                           | `PostgreSQLInstance` becomes `PostgreSQLCluster`; users and databases name it in `clusterRef`.                                                                                                                                                                                                                  |
| Class, parameters and provider kinds<br>Added, PostgreSQL             | `PostgreSQLClass`, `PostgreSQLParameters` and a provider configuration kind per implementation.                                                                                                                                                                                                                 |
| `vector` extension allowed<br>Added, PostgreSQL                       | `PostgreSQLDatabase` allows the `vector` extension (pgvector), which today's API allows since release `v0.2.104`.                                                                                                                                                                                               |
| Server kind renamed<br>Changed, MariaDB                               | `MariaDBInstance` becomes `MariaDBServer`; users and databases name it in `serverRef`.                                                                                                                                                                                                                          |
| Class, parameters and RDS kind<br>Added, MariaDB                      | `MariaDBClass`, `MariaDBParameters` and `MariaDBRDSConfig`.                                                                                                                                                                                                                                                     |
| Server kind and replicas renamed<br>Changed, Valkey                   | `ValkeyInstance` becomes `ValkeyServer`, and `replicas` becomes `readReplicas`.                                                                                                                                                                                                                                 |
| Class, parameters and provider kinds<br>Added, Valkey                 | `ValkeyClass`, `ValkeyParameters` and a provider configuration kind per implementation.                                                                                                                                                                                                                         |
| Class, parameters and provider kinds<br>Added, Kafka                  | `KafkaClass`, `KafkaParameters` and a provider configuration kind per implementation for `KafkaCluster`.                                                                                                                                                                                                        |
| Topic defaults from the class<br>Added, Kafka                         | A `KafkaTopic`'s defaults come from its cluster's `KafkaClass` (`topicTemplate`).                                                                                                                                                                                                                               |
| Prefix matching for ACLs and groups<br>Added, Kafka                   | A `KafkaUser`'s ACLs and consumer groups match a name exactly or by its prefix (`patternType`).                                                                                                                                                                                                                 |
| Class, parameters and Amazon MQ kind<br>Added, RabbitMQ               | `RabbitMQClass`, `RabbitMQParameters` and `RabbitMQAmazonMQConfig` for `RabbitMQBroker`.                                                                                                                                                                                                                        |
| Maintenance window flattened<br>Changed, RabbitMQ                     | `RabbitMQBroker`'s `maintenance.window` becomes `maintenanceWindow`.                                                                                                                                                                                                                                            |
| Non-empty bucket never deleted<br>Changed, Bucket                     | Deleting a `Bucket` that still holds objects fails on every implementation, with the cloud's error in its status; the platform never deletes a bucket's objects.                                                                                                                                                |
| Class and provider kinds<br>Added, Bucket                             | `BucketClass` and a provider configuration kind per implementation for `Bucket`, which holds the `id` of a bucket to observe.                                                                                                                                                                                   |
| Class and provider kinds<br>Added, ArtifactRepository                 | `ArtifactRepositoryClass` and a provider configuration kind per implementation for `ArtifactRepository`.                                                                                                                                                                                                        |
| Defaults from the class<br>Changed, ArtifactRepository                | `ArtifactRepository`'s `immutableTags` and `lifecycleRules` default from the class.                                                                                                                                                                                                                             |
